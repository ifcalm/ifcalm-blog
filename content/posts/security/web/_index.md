## 分类：信任在哪一环断掉

Web 的攻击面沿着一条请求链条铺开——**从浏览器发出请求，到服务端解析、鉴权、取数、调外部服务，再到这堆代码是怎么装到机器上的**。分类就按信任在哪一环断掉来分。

```
浏览器 ──▶ 边缘/解析 ──▶ 认证 ──▶ 授权 ──▶ 业务逻辑 ──▶ 出站请求 ──▶ 数据
   W4          W1 W5        W2       W3                    W6
                                              W7 configuration 贯穿全程，且横跨每一环
```

| | 类别 | 失效的假设 | 代表事件 |
|---|---|---|---|
| **W1** | 注入 | "数据和代码是分开的" | Samy 蠕虫 2005 · Struts/Equifax 2017 · Log4Shell 2021 · MOVEit 2023 |
| **W2** | 认证与会话 | "拿着这个凭据的就是本人" | Twitter 内部面板 2020 · Uber 2022 · Snowflake 2024 |
| **W3** | 访问控制 | "他访问不到的，他就看不见" | 顺序 ID 越权（IDOR）的历次大规模泄露 |
| **W4** | 浏览器信任边界 | "同源策略会替我挡住" | CSRF · CORS 配错 · clickjacking · postMessage 无来源校验 |
| **W5** | 内存与解析 | "解析器不会读到它不该读的地方" | Heartbleed 2014 · Shellshock 2014 · Cloudbleed 2017 |
| **W6** | 供应链 | "装下来的包 = 作者写的包" | event-stream 2018 · SolarWinds 2020 · Codecov 2021 · xz-utils 2024 |
| **W7** | 配置与暴露 | "默认值是安全的" | 公开的对象存储桶 · 暴露的管理端口 · 进了 git 的密钥 |

## 每一类要回答的问题

```
W1  注入的一般形式：解析器把你的数据当成了它的语法
    为什么"过滤危险字符"是错的解法，参数化/上下文编码为什么是对的
    SQL · 命令 · 模板 · 表达式语言（OGNL/SpEL）· 反序列化 · XSS 的存储型与 DOM 型

W2  会话凭据的完整生命周期：签发、传输、存储、续期、撤销
    密码存储 · MFA 的绕过方式（疲劳轰炸、SIM 劫持、令牌重放）
    OAuth 的重定向与 state · JWT 的四类经典误用 · 会话令牌泄露后能做什么

W3  越权的两种形态：横向（换一个 ID）与纵向（换一个角色）
    为什么"前端不显示"从来不是访问控制
    鉴权应该放在哪一层，以及为什么放在网关上通常不够

W4  同源策略实际保护什么、不保护什么
    CSRF 与 SameSite · CORS 的 credentials 陷阱 · clickjacking
    postMessage / iframe / 第三方脚本的信任边界

W5  内存越界读为什么会泄露别人的数据（Heartbleed 的一个长度字段）
    边缘代理的状态串扰 · 环境变量与解析器状态被污染

W6  依赖投毒 · 抢注（typosquatting）· 维护者账号被接管
    构建流程本身被改 · CI 令牌的权限范围
    锁文件、来源校验、可复现构建各自能挡住什么

W7  暴露的管理端口 · 默认凭据 · 调试模式 · 目录列举 · .git 暴露
    对象存储的权限模型 · 密钥进了版本库之后要做的事（轮换 ≠ 删 commit）
```

## 每篇的结构

```
一、事件经过      时间线、影响范围、怎么被发现的
二、原理          漏洞的机制，精确到那一行/那一个字段
三、攻击复盘      攻击者一步步做了什么，含请求构造
四、为什么没被拦住  测试、评审、WAF、扫描器为什么都没起作用
五、防御          正确的写法，以及为什么那样写就安全
六、举一反三      同一条假设还会出现在哪里
七、本案小结
   思考题
```

「原理」和「防御」是重点。只讲"某某公司泄露了多少条数据"、给不出机制的事件，**不收**。

## 和链上安全的关系：基本没有

同在 `security/` 下只是因为都叫安全，**两支的技术内容几乎不重叠**，不必对照着读。真正的差别在执行环境：

- Web 侧可以打补丁、可以回滚、可以在事中止损，所以防御是**纵深**的——事前、事中、事后都有手段。
- 链上侧只有事前防御。

这条差别决定了两边连"什么算防御"都不是一回事：Web 侧的 WAF、限流、审计日志、应急响应在链上都不存在对应物；链上侧的形式化验证、不变量断言、经济博弈分析在 Web 侧也很少用得上。
